# 临床文书智能工作流自动化原型

> 基于 AI-assisted coding 的个人医疗场景自动化原型项目

## 一、项目简介

本项目是一个面向临床文书重复操作场景的个人技术验证原型。

项目尝试将临床工作中的重复性操作拆解为：

> 信息采集 → 信息识别 → 文本处理 → 原子操作 → 工作流编排 → 自动执行

并结合屏幕采集、图像处理、OCR、文本处理、模拟键鼠控制和可视化工作流配置等方式，验证桌面医疗信息处理流程自动化的可行性。

本项目目前仍处于 Prototype（原型验证）阶段，未部署至生产环境，也不构成医疗软件、临床决策支持系统或医疗器械。

---

## 二、项目背景

临床文书处理中存在大量重复性的跨页面信息搬运与界面操作。

典型流程包括：

1. 获取页面中的检验、检查或医嘱信息；
2. 定位目标区域；
3. 对页面内容进行识别；
4. 对识别结果进行清洗、结构化和规则处理；
5. 将处理结果用于后续文书操作；
6. 按照预先定义的步骤完成重复性界面操作。

本项目希望探索：

> 能否将这些复杂流程拆解成可复用的原子任务，并通过工作流进行组合和执行。

## 四、核心设计思路
1. 原子工作流

复杂操作被拆解为较小的步骤，例如：

定位页面
↓
定位目标区域
↓
执行键盘操作
↓
执行鼠标操作
↓
等待
↓
执行下一步骤

工作流引擎负责依次执行这些步骤，并维护运行过程中的状态。

2. 工作流编排

在原子工作流之上进一步使用“编排”组织多个工作流。

例如：

工作流A
   ↓ 成功
工作流B
   ↓ 成功
工作流C

失败
 ↓
备用工作流

从而将较复杂的任务组织成可管理的流程。

3. OCR与文本处理分离

项目将：

OCR识别

与：

OCR结果处理

分开设计。

OCR引擎负责识别，文本处理器负责进一步进行：

表格切分
文本清洗
项目名称处理
检验结果处理
检查结果处理
医嘱提取

并通过处理器注册与调度机制组织不同类型的处理逻辑。

## 五、OCR方案

项目针对特定、相对稳定的桌面文本显示环境进行了 OCR 相关实验。

除通用图像处理外，还尝试使用：

特定颜色提取
二值化
字符模板
位图匹配
哈希检索
滑动窗口
文本后处理
正则规则

等方法进行特定场景下的文字识别。

其中部分 OCR 引擎针对不同字体尺寸和页面显示环境进行适配。

本项目并不试图构建通用 OCR 系统，而是探索：

在显示环境可控的情况下，能否通过规则与模板方法降低识别复杂度。

## 六、JSON工作流编辑

项目包含独立的 JSON 工作流配置工具。

可以通过图形界面：

添加步骤
删除步骤
调整步骤顺序
编辑步骤参数
编辑条件分支
保存工作流配置

从而减少直接手写 JSON 配置的成本。

## 八、原型测试结果

在受控测试环境下，对病案首页相关流程进行了前期原型验证。

测试结果：

可替代约80%以上人工填写步骤；
减少近百次键盘/鼠标交互；
单次流程可压缩至2分钟以内。

上述数据属于前期原型测试结果，不代表生产环境性能指标。
